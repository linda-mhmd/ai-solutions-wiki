Claude is Anthropic's family of large language models, designed with a focus on safety, reliability, and extended context handling. For enterprise AI applications, Claude is one of the most widely deployed models via Amazon Bedrock, where it is available across multiple capability tiers — and, as of September 2026, also via Google Cloud, Microsoft Foundry, and Anthropic's own Claude Platform on AWS.

## Model Tiers

As of 25 September 2026, Anthropic's current lineup spans five named models across four tiers, all sharing the same API and the same general capability profile (tool use, long context, strong instruction following) at different price/performance points. Model IDs in the 5 generation are dateless pinned snapshots; Haiku's is an alias that resolves to a dated snapshot, which matters if you pin versions in production.

**Haiku** (`claude-haiku-4-5`, an alias for the pinned snapshot `claude-haiku-4-5-20251001`) - The fastest and most cost-efficient tier, with a 200K-token context window and a 64K maximum output. Best for high-volume, lower-complexity tasks: classification, short-form extraction, simple summarization, intent detection. At $1/$5 per million tokens against Sonnet 5's $2/$10, Haiku costs exactly **half** Sonnet's per-token price - a real saving, but a much narrower one than earlier Haiku generations offered against their contemporary Sonnet, so build the cost model on the current numbers rather than on the old order-of-magnitude intuition. Haiku 4.5 is also the odd one out in the lineup in three ways: released 15 October 2025, it is the only current model still on the previous tokenizer, the only one that does not support the `effort` parameter (it uses manual extended thinking with `budget_tokens`), and the one closest to end of life - Anthropic's published floor is that it will not retire before 15 October 2026. No deprecation has been announced, and Anthropic commits to at least 60 days' notice for publicly released models, so it cannot arrive unannounced - but Haiku 4.5 is the model in the current lineup to keep a migration plan for. Its knowledge cutoff (February 2025) is also by far the oldest on offer.

**Sonnet** (`claude-sonnet-5`) - The middle tier, balancing capability and cost, with a 1M-token context window and 128K maximum output. Anthropic released Claude Sonnet 5 on 30 June 2026 for agentic and automation workloads, at performance close to the prior-generation flagship, Opus 4.8. Its introductory pricing was scheduled to rise 50% on 1 September 2026; Anthropic cancelled that increase on 10 August 2026 and made the introductory rate the permanent standard price instead. A standing note to that effect now sits on Anthropic's own pricing page, so this is settled rather than provisional. See [Anthropic cancels the Sonnet 5 price rise](/news/claude-sonnet-5-pricing-permanent/). Sonnet 5 uses adaptive thinking steered by the `effort` parameter (default `high`); manual extended thinking and non-default `temperature`, `top_p` or `top_k` all return a 400. For most enterprise knowledge-worker tasks (document review, draft generation, data analysis, high-volume agentic automation), Sonnet 5 provides the best practical value. **Claude Sonnet 5.5 shipped on 28 September 2026** as `claude-sonnet-5-5`, at the same $2/$10 per MTok as Sonnet 5, with cache reads at $0.20 and cache writes at $2.50. Anthropic says it runs more than 30% faster than Sonnet 5 and costs up to 30% less for most work, because it uses fewer tokens per task as well as costing less per token. It ships safety classifiers aimed at distillation attacks, cybersecurity safeguards comparable to Opus 5.5, and the same biology safeguards as Sonnet 5, and it is available on the Claude Platform, AWS, Google Cloud and Microsoft Azure with a zero data retention option. Anthropic did not publish its context window or maximum output in the release post. Claude Haiku 5.5, announced in the same 22 September statement, has still not shipped. See [Claude Sonnet 5.5 lands at $2/$10, faster and cheaper than Sonnet 5](/news/claude-sonnet-5-5/). For new Sonnet-tier work, start on Sonnet 5.5.

**Opus** (`claude-opus-5-5`) - The general-purpose flagship for long-running agentic coding and knowledge work, at 1M context and 128K maximum output (300K on the Message Batches API behind the `output-300k-2026-03-24` beta header). **Claude Opus 5.5 reached general availability on 22 September 2026** (see [Claude Opus 5.5 launches at $4/$20, with thinking always on](/news/claude-opus-5-5/)), the first model in Anthropic's new Claude 5.5 family, and it is where Anthropic's own documentation now tells you to begin: "If you're unsure which model to use, start with Claude Opus 5.5 for most workloads." Anthropic says it "performs at the level of Claude Fable 5.1 on most work and costs 40% less to run than Opus 5" — the 40% figure combines a 20% per-token price cut (**$4/$20 per MTok**, against Opus 5's $5/$25) with fewer tokens used per task on Anthropic's own tests, so treat it as a vendor estimate to re-measure on your workload. Cache reads cost **$0.20/MTok** (5% of input, a multiplier specific to Opus 5.5). Its reliable knowledge cutoff is June 2026, the default `effort` is `medium` (not `high` as on Fable 5.1 and Sonnet 5), and adaptive thinking is **always on**: `thinking: {"type": "disabled"}` and manual `"enabled"` both return a 400. Forced `tool_choice` (`"any"` or a named `"tool"`) also returns a 400, as on Fable 5.1; so do non-default `temperature`, `top_p` or `top_k` and a prefilled final assistant turn (both already rejected on recent Opus models); and on the Claude API and Google Cloud computer use requires `computer_toolset_20260801` (Bedrock still accepts `computer_20251124`). Anthropic's migration guide lists these changes for teams moving off Opus 5. Opus 5.5 is also the first Opus model to launch with Fable 5.1-class safeguards: a biology classifier alongside the cybersecurity one, and **most cybersecurity tasks are re-routed to Opus 4.8** (Anthropic says routine find-and-fix of bugs in your own code is still handled). Its retirement floor is 22 September 2027. Anthropic's Opus 5.5 model pages do not list the 30-day-retention requirement that applies to Fable 5.1 and Mythos 5.1; AWS states that Opus 5.5 on Amazon Bedrock has zero data retention support by default, but Anthropic has not published an equivalent statement for its first-party API, so confirm ZDR eligibility with your account team before moving a ZDR workload there.

Claude Opus 5 (`claude-opus-5`, GA 24 July 2026) is now **previous generation, superseded by Opus 5.5**: Anthropic's models overview has moved it to "Legacy models (still available)", and the deprecations table still lists it Active with a retirement floor of 24 July 2027. Anthropic documents it as available under zero-data-retention arrangements. Adaptive thinking on Opus 5 can still be disabled at effort `high` or below, which is the practical reason some integrations may stay on it while they migrate.

**Fable** (`claude-fable-5-1`) - Anthropic's most capable widely released model, positioned above Opus for the most demanding programming and long-horizon knowledge work, also at 1M context and 128K maximum output. Claude Fable 5.1 reached general availability on 1 September 2026, at the same headline per-token price as its predecessor, Fable 5, but with prompt-cache-read pricing cut 75% (from $1 to $0.25 per million tokens) — a change that disproportionately benefits agentic, tool-heavy workloads that repeatedly re-read cached context. Being the most capable model does not make it the default: Anthropic's guidance is to start on Opus 5.5 and reach for Fable 5.1 "for demanding reasoning and long-horizon agentic work, or when your evals on Claude Opus 5.5 at higher effort still fall short." With Opus 5.5 priced at 40% of Fable 5.1's per-token rate and claimed to match it on most work, the case for Fable 5.1 now has to be made on evals rather than assumed. See [Claude Fable 5.1 reaches general availability, Mythos 5.1 stays gated](/news/claude-fable-5-1-mythos-5-1-ga/).

**Mythos** (`claude-mythos-5-1`) - The same capabilities and specifications as Fable 5.1, offered to cybersecurity defenders and life-sciences researchers who need capabilities the general-availability safeguards would otherwise block. Unlike every other tier above, Mythos 5.1 is **not** self-serve: access runs through Anthropic's vetted-access programs and, at launch, is limited to a set of US organizations, with expansion planned through government coordination with domestic and international partners. Which program actually reaches Mythos 5.1 *today* is worth reading carefully. The Life Sciences Verification Program (LSVP) — developed in partnership with the US government — is the one that grants Mythos 5.1 access now. The Cyber Verification Program (CVP), as of the 1 September announcement, still provides access only to certain Opus- and Sonnet-class models with reduced cyber safeguards for defensive security work; Anthropic says the program "will also include access to Claude Mythos-class models" in the near future, but that is a stated plan, not a shipped capability. A defensive-security team should not assume CVP enrolment currently yields a Mythos 5.1 key. Anthropic's docs direct prospective users to their Anthropic, AWS, or Google Cloud account team. Pricing is identical to Fable 5.1 ($10/$50 per MTok, $0.25/MTok cache reads) for the organizations that qualify. One platform difference is easy to miss: Mythos 5.1 is listed on the Claude API, Amazon Bedrock, Google Cloud and Microsoft Foundry, but **not** on Claude Platform on AWS, which Fable 5.1 does support.

How much lighter Mythos's safeguards are is less clearly documented than the access program. For the previous generation Anthropic said it plainly: Fable 5 "includes safety classifiers that can decline requests, and Claude Mythos 5 does not." For 5.1 the migration guide files safety classifiers under where the two models diverge and describes only Fable 5.1's behavior, while still telling Mythos 5.1 integrators to handle `stop_reason: "refusal"` and read `stop_details.category`. The lighter-safeguard framing is directionally right, but Anthropic has not restated it for this generation, so do not design around an assumption that Mythos 5.1 never refuses.

**Deployment constraints specific to Fable 5.1 and Mythos 5.1.** Both models require 30-day data retention and are not available under zero-data-retention arrangements unless Anthropic expressly authorizes it; a request from an organization or workspace without 30-day retention returns a 400 `invalid_request_error`. Both are designated Covered Models, neither is supported on Priority Tier, text they generate carries an Anthropic watermark, and media produced by the code execution tool carries C2PA Content Credentials. For a regulated buyer on a ZDR contract, that is the binding constraint on the entire top tier — Opus 5, by contrast, is available under ZDR. Three API behaviors also changed at 5.1 relative to Fable 5: forced `tool_choice` (`"any"` or `"tool"`) now returns a 400, thinking blocks are readable only by the model that produced them or a newer one, and on Fable 5.1 editing an earlier turn invalidates thinking blocks (Mythos 5.1 does not run that check).

Anthropic also continues to serve the previous generation for existing integrations: Opus 5 (24 July 2026), Fable 5 and Mythos 5 (both released 9 June 2026), Opus 4.8, 4.7, 4.6 and 4.5, and Sonnet 4.6 and 4.5. "Legacy" is a defined lifecycle term — no further updates, possible deprecation later — but it is not deprecation: the models overview files Fable 5, Opus 5, the four Opus 4.x releases and the two Sonnet 4.x releases under "Legacy models (still available)", their model pages read **Active (legacy)**, and the model-deprecations table that actually governs support commitments lists every one of them as **Active** with no deprecation announced. Mythos 5 appears in neither list, because invite-only models are omitted from both; its own model page reads **Active (invite only)**, with the same 9 June 2027 retirement floor as Fable 5. Most of those have retirement floors in 2027, but two are close: **Sonnet 4.5 may retire no sooner than 29 September 2026** — four days from this update — and Opus 4.5 no sooner than 24 November 2026. Neither has a formal deprecation notice yet, and Anthropic commits to at least 60 days' notice, so neither can actually retire on its floor date; but they are the first two to plan off. Two differences are worth knowing before leaving a Fable 5 integration in place — its cache reads cost $1.00/MTok rather than $0.25, and it *is* supported on Priority Tier, which Fable 5.1 is not. Further back, Opus 4.1 retired on 5 August 2026 and Opus 4 and Sonnet 4 on 15 June 2026; those are now reachable only through the partner platforms that still list them. Anthropic's published replacement for all three is the prior generation, not the current flagship — Opus 4.1 and Opus 4 point at `claude-opus-4-8` and Sonnet 4 at `claude-sonnet-4-6`, because each deprecation was announced before Opus 5 shipped. Treat those notices as the minimum safe landing spot, not the destination: for new work, Sonnet 5, Opus 5.5, and Fable 5.1/Mythos 5.1 are the recommended defaults at their respective tiers.

## Key Strengths

**Long context window** - Sonnet 5, Opus 5.5, Opus 5, Fable 5.1, and Mythos 5.1 all support context windows up to 1 million tokens — roughly 555,000 words on the current tokenizer (introduced with Opus 4.7, which Anthropic says produces about 30% more tokens per unit of text than the previous one; its own word-count figures, 750,000 words per million tokens before and 555,000 after, imply closer to 35%) — billed at standard per-token rates across the full window, with a 128K maximum output. Opus 5.5, Opus 5 and Sonnet 5 can go to 300K output on the Message Batches API behind the `output-300k-2026-03-24` beta header; Fable 5.1 and Mythos 5.1 cannot. Haiku 4.5, which still uses the previous tokenizer, supports 200K tokens (roughly 150,000 words) and 64K of output. For document generation and long-form synthesis the output ceiling binds long before the context window does, so size both. This means entire books, large codebases, or extensive document sets can be processed in a single call without chunking. For RAG pipelines where traditional chunking limits retrieval quality, Claude's long context can process entire source documents directly.

**Instruction following** - Claude reliably follows complex, structured instructions, including multi-part JSON output schemas, tone and style constraints, and conditional logic instructions. This makes it well-suited for applications with strict output format requirements.

**Reduced hallucination on constrained tasks** - When instructed to answer only from provided context and to acknowledge when information is not present, Claude follows these constraints reliably. This is critical for enterprise knowledge base applications where accurate sourcing matters.

**Code tasks** - Claude performs well on code generation, debugging, and documentation tasks, including less common languages and frameworks. Fable 5.1 in particular is positioned by Anthropic specifically around programming and long-running agentic problem-solving, with reported benchmark gains over Fable 5 on coding- and tool-use-heavy evaluations.

## Access Options

Claude is available through:
- **Anthropic API** - Direct API access with usage-based pricing
- **Amazon Bedrock** - Access via Bedrock API with AWS IAM, VPC, and compliance controls; data stays within your AWS account; pricing is partner-operated and set independently by AWS
- **Claude Platform on AWS** - Anthropic's own AWS Marketplace listing, billed in Claude Consumption Units (CCU) at Anthropic's standard per-model rates, so usage shows as a single line item on your AWS bill
- **Google Cloud** - via the Gemini Enterprise Agent Platform (formerly Vertex AI); see [Google Vertex AI](/tools/google-vertex-ai/) for what changed in that rebrand
- **Microsoft Foundry** - billed through the Azure Marketplace, also using Claude Consumption Units at standard first-party rates
- **Claude.ai** - Web and API interface for direct use and team collaboration features

Coverage is not uniform across the lineup, so check it per model rather than per vendor. Opus 5.5, Sonnet 5, Haiku 4.5 and Fable 5.1 are listed on all of these paths — for Opus 5.5 the model page, the models comparison table and the 22 September API release note agree, including Claude Platform on AWS. AWS's launch notes add that Opus 5.5 is also available in AWS GovCloud (US) and that on Bedrock it comes with zero data retention (ZDR) support by default. Mythos 5.1's availability row omits Claude Platform on AWS. The previous-generation Opus 5 remains the awkward case, because Anthropic's own pages disagree: its model page lists only the Claude API, Amazon Bedrock, Google Cloud and Microsoft Foundry, but the API release note dated 24 July 2026 says Opus 5 *is* available on Claude Platform on AWS. For new work on that path, Opus 5.5 removes the question.

For enterprise deployments requiring data residency controls, compliance certifications (SOC 2, HIPAA BAA), and IAM integration, Bedrock or Claude Platform on AWS is typically the preferred access path — with one caveat worth pricing in: that first-party data residency is not free: setting `inference_geo: "us"` applies a 1.1x multiplier to every token category (input, output, cache writes and cache reads) on Claude 4.6 and later models, on the Claude API and Claude Platform on AWS, and on Foundry's US Data Zone Standard deployments. An organization whose cloud commitment is specifically with Google Cloud is, as of this writing, the one procurement path that reaches Claude but not OpenAI's frontier models, since OpenAI does not offer GPT-5.6 or newer through Vertex AI's Model Garden.

| Claude Sonnet 5.5 | $2.00 | $2.50 / $4.00* | $0.20 | $10.00 | not published |

| Claude Mythos 5.1 *(verified orgs only)* | $10.00 | $12.50 / $20.00 | $0.25 | $50.00 | 1M / 128K |

Notes:
- \* Anthropic published Sonnet 5.5's cache-write rate as $2.50; the 1-hour figure above follows the documented 2x-of-input rule rather than a separately published number. The release post did not state Sonnet 5.5's context window or maximum output, so those cells stay empty rather than inheriting Sonnet 5's.
- Sonnet 5's $2/$10 rate was introductory pricing through 31 August 2026, scheduled to rise 50% to $3/$15; Anthropic cancelled that increase on 10 August 2026 and made $2/$10 the permanent standard rate.
- Cache **writes** cost 1.25x the base input rate for the 5-minute TTL and 2x for the 1-hour TTL, on every model. Cache **reads** cost 10% of the base input rate on every model except Fable 5.1 and Mythos 5.1, which use a sharper 2.5% multiplier, and Opus 5.5, which uses 5% ($0.20/MTok). Anthropic notes cache reads make up the majority of agentic and coding costs, so on cache-heavy workloads Opus 5.5's saving over Opus 5 ($0.20 vs $0.50) is larger than the 20% headline per-token cut. Caching pays back only when the write premium is amortized over enough reads, so compute it from both columns rather than the read column alone.
- The Batch API discounts input and output tokens 50% on every model above (asynchronous, non-latency-sensitive workloads only).
- **Modifiers that do not appear in the table but do appear on the bill**: `inference_geo: "us"` adds a 1.1x multiplier to every token category on Claude 4.6 and later (Claude API, Claude Platform on AWS, and Foundry US Data Zone Standard deployments); fast mode, a research preview available on Opus 5.5, Opus 5 and Opus 4.8 through the Claude API only, bills at $8/$40 per MTok on Opus 5.5 (Anthropic claims up to 2.5x faster output) and $10/$50 on Opus 5 and Opus 4.8 — double each model's standard rate; and Claude Managed Agents adds a session-runtime charge of $0.08 per session-hour on top of tokens.
- **Tool pricing is separate from tokens**: web search is $10 per 1,000 searches, web fetch is free, and code execution is free when paired with web search or web fetch, otherwise $0.05 per container-hour beyond 1,550 free hours per organization per month.
- **Amazon Bedrock and Google Cloud are partner-operated**: pricing is set independently by AWS and Google and can differ from the first-party rates above — check [Bedrock pricing](https://aws.amazon.com/bedrock/pricing/) or [Google Cloud pricing](https://cloud.google.com/vertex-ai/generative-ai/pricing#claude-models) directly.
- **Claude Platform on AWS and Claude in Microsoft Foundry** are Anthropic-operated and bill at the same rates as the table above, converted to Claude Consumption Units ($0.01/CCU) for marketplace invoicing.
- Pricing changes over time - always check the [current Anthropic pricing page](https://platform.claude.com/docs/en/about-claude/pricing) before building cost models for production workloads.

## The Claude Product Family

Beyond the models and the chat apps, Anthropic ships several products built on the same Claude models. They differ mainly in where they run and what they produce.

| | Where it lives | What it is for | Plan needed |
